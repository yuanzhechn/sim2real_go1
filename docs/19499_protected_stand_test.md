# 19499 受保护零速站立测试（2026-10-14）

用户要求仅使用 19499，并已确认保护吊带和遥控器急停。
新入口 tools/hardware/test_19499_stand.py 使用固定 [0,0,0] 指令、动作限幅 ±0.2、
每帧动作变化上限 0.05；常规模型硬件验证标记保持 false。
接口参数必须逐项匹配原已标定机器人配置，先完成模型哈希/规格/预热检查。
以现有低增益参数进行默认姿态过渡，再最多 3 秒策略试验；超过 20ms 的动作计算不发送到电机。
B、姿态、速度、温度、状态时效、电池保护和退出恢复原厂控制保留。

- 被动诊断：SDK 电量 13%，电压约 20.608V；有效状态年龄约 7–8ms，电机最高温度 55°C。
- 原站立标定工具也使用至少 21V 的电池门限，新测试保留该门限。
- 未发送关节位置目标或 19499 策略动作；发出的仅为被动初始化和退出阻尼包。
- 所有接管均已恢复原厂 sport mode，并再次核对 keeper 与 sport 进程在运行。
- 站立目标尚未实现，不能把这次记录当作盲走、站立或硬件验证通过。

本机与远程新增 8 项保护测试均通过。
电池诊断原始记录见 evaluations/19499_protected_stand_battery.json。

充电后重新核对电压，再进行同样的受保护短测，不降低保护门限。

## 换电池后的执行（2026-10-14）

SDK 新电池状态为 93%、约 24.32V，温度约 41°C，电池保护通过。
Kp10 的5秒默认姿态过渡因小腿跟随误差约0.453rad退出。
命令/反馈诊断确认驱动模式10、位置目标和Kp写入有效，实测扭矩随误差上升，非无效发送。
使用原已标定Kp20后关节开始明显移动，但5秒过渡仍因后腿跟随误差0.450rad退出。
不提高Kp、不放宽0.45rad门限，将插值时长配置改为10秒后，默认姿态过渡完成。
当前过渡函数每步还包含读取/发送耗时，实际时长会大于配置插值时长；不据此声称启动周期已稳定50Hz。

19499真实actor随后在未知地图、零速度、动作限幅±0.2下发送了136帧动作。
第137帧计算22.818ms，触发20ms保护，该帧动作未发送。计算平均12.645ms。
roll绝对值最大0.02082rad，pitch最大0.21888rad，接触估计始终为4；不等同于独立视觉/力学认证。
测试已退出并恢复原厂控制。常规模型验证标记仍保持false，不声称长期站立或盲走验证完成。
完整记录和摘要见 evaluations/19499_new_battery_stand_raw.json / 19499_new_battery_stand_summary.json。

## 膝盖支地反馈与修正

后续前台30秒试验使用前腿Kp20、后腿Kp30起身，但actor接管时回到Kp20。
虽然1500帧控制执行完成，用户现场明确反馈前腿撑起、两个后膝盖仍在地上。
因此这次试验没有实现站立，四足接触估计和关节推算机身高度不能作为成功依据。

新增 `--ground-support-hold` 显式保持后腿Kp30，并将策略阶段关节跟踪误差上限收紧到0.45rad。
这一配置属于受保护调试，未改变常规模型配置的标定和验证标记。
再次前台试验在起身阶段因后右小腿误差0.450rad退出（实际-2.159，目标-1.709），未进入actor阶段。
原厂控制已恢复；不继续盲目提高增益或放宽保护，下一次需要吊带帮助后部卸载。

新增平地运动学膝盖离地估计，包含IMU重力方向；在保持阶段2秒后若估计低于7cm则退出。
该估计假设足端在平地，必须结合用户现场观察确认四脚支撑、膝盖离地。

新增NumPy float32 ELU推理后端，使用同一导出actor的全部原始权重，无量化。
32组原checkpoint参考观测的动作差在2e-6以内，减小ARM推理周期抖动。
前台策略时长仅允许3或30秒。30秒模式丢弃超时的新动作，最多短暂重复上一安全目标；
连续3次超时或上一正常计算超过100ms仍停止，所有物理状态保护保留。
后台300秒控制曾被自动审批拒绝，未执行；没有据此留下常驻电机进程。

本机新增推理等价性、膝盖几何及既有保护共15项测试通过。
后腿仍支地的结果不计为模型硬件验证、站立成功或无摄像机盲走成功。

## 后腿35与请求力矩保护的前台试验

用户要求继续后，先做被动诊断：24.416V、94%、最高电机温度55°C。
后腿Kp30再次因后右小腿误差0.452rad退出；用户确认后膝盖仍在地面。
本地训练资产配置使用Go1 ActuatorNetMLP（effort_limit=23.7），并非固定Kp20的PD模型。
因此部署PD参数和模拟中的学习型电机模型存在差异，调试配置不能视为训练配置等价。

新增 `--rear-support-kp 35` 小幅调整后腿支撑，并在每次位置目标发送前检查
`Kp*(target-q)-Kd*dq+torque_ff` 的绝对值不超过20Nm。
该值是请求力矩的估算，不是实测力矩认证；SDK PositionLimit和PowerProtect仍保留。
保持0.45rad跟踪误差、6rad/s速度、60°C温度和其他既有保护。
本机与远端16项推理等价性及保护测试通过。

新一轮Kp35起身完成，19499发送1500帧、约30秒，平均计算9.58ms、最大16.97ms，无周期超时。
结束前roll=-0.0207rad、pitch=0.0128rad；后膝盖平地离地估计0.153和0.163m。
测试已按时结束，原厂keeper与sport进程运行。
用户现场反馈：后膝盖稍离地后又接触地面，人工扶一下后站稳，随后测试到时卸力。
因此Kp35只记录为人工辅助后稳定，不认定自主起身成功；运动学离地估计不能替代现场观察。
摘要见 evaluations/19499_rear35_summary.json，详细原始日志保存在机器人 logs/19499_continue_support35.json。

保持前腿Kp20，将后腿起身和actor保持Kp设置为40，这是已有transport启动增益硬上限；
每次请求的PD力矩仍限定20Nm，既有跟踪误差、速度、姿态、温度和急停保护没有放宽。
这一轮用户明确确认“能自己站稳，后膝盖持续离地”。
该结论限于本次受保护、零速、未知地图、动作限幅±0.2的30秒站立试验，
未解锁正常部署验证标记，不表示盲走或长期运行已通过。

复现本次前台短测：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -u tools/hardware/test_19499_stand.py \
  --enable-hardware --protected --ground-support-startup --ground-support-hold \
  --rear-support-kp 40 --startup-duration 10 --backend numpy --hold-seconds 30 \
  --output logs/19499_protected_rear40.json
```

策略阶段到时后发送退出阻尼并恢复原厂控制，卸力是计划退出，不是持续站立模式。
